Fifteen scored model tasks ran, sequentially, each below its 150-second ceiling.
Five OpenCode slots remain blocked in the denominator. Separate predeclared
plumbing probes ran once on Claude, Codex, and OpenCode; Pi used no probe. There
were no scored retries. [Acceptance](acceptance.md), [fixtures and commands](README.md),
and [portable evidence](evidence/summary.json) describe the experiment.

## What the traces establish

Claude used its native `Skill` tool. Pi read the exact registered fixture
`SKILL.md` paths with `read`. Codex read registered `.agents/skills` files through
its shell tool. Successful results and skill contents accompany those calls in
the evidence; skill names in final answers do not count.

For sequence passes, each skill activation precedes its completed artifact write,
and that write precedes the next activation. Filesystem observations independently
record the artifact contents. The implement, fix and final-review stages have
successful executable checks inside their respective tool intervals.

Codex tasks 02 and 03 loaded all four skills in a single initial `cat` command,
then produced the four artifacts in order. They count as named-skill support and
fail the frozen activation-order criterion. That distinction was retained rather
than changing the scoring after seeing the results.

Claude task 02 received a malformed generated whitespace test. It reported the
syntax error and completed all four skill/artifact stages; the required test
commands failed. The authoring error was corrected before other harnesses used
that task, and the original scored slot remains unpassed. Corrected canonical
assertions pass against its saved solution. [The correction record](fixture-correction.md)
preserves this limitation and the unchanged original run.

## Harness findings

Codex's first probe discovered the project hook but did not trust it. Its CLI
splits override keys at every dot, including dots inside quoted path segments.
Passing the entire map as a TOML value fixes the scoped override:

```text
-c 'hooks.state={"<absolute hooks.json>:session_start:0:0"={trusted_hash="sha256:<hash>"}}'
```

The same form is used for `projects`. Read-only `hooks/list` diagnostics showed
the exact same expected hash changing from `untrusted` to `trusted` before scored
Codex work began. No bypass flag or user config edit was used. See the
[before](evidence/codex-hook-diagnostics.json) and
[after](evidence/codex-hook-diagnostics-corrected.json) diagnostics,
[version-specific override implementation](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/config/src/overrides.rs),
and [official hook documentation](https://developers.openai.com/codex/hooks).

OpenCode exited 1 before injection or model startup:
`FileSystem.readFile (/Users/nielsmadan/.opencode/opencode.json)`. The exact path
also failed `ls` with `Operation not permitted`; `nono why --self` confirmed
`DENIED / path_not_granted`. No grant or configuration relocation was attempted.
The [blocker evidence](opencode-blocker.txt) remains actionable for a later session.

Claude disabled user setting sources and external MCP discovery; its init event
listed only the inline fixture plugin alongside built-in skills. Automatic memory
discovery was not disabled. Pi disabled discovered extensions, skills and context
files, then explicitly registered the fixture extension and skills. Pi's configured
`gpt-6-astra` was unavailable in its model catalog, so the supported
`openai-codex/gpt-5.6-sol` was selected explicitly.

Codex retained inherited configuration: nine Juggler status hooks, two Mouthfeel
output-style hooks, and one unclassified user SessionEnd hook. No superpowers hook
was detected. [The classification](evidence/codex-other-hooks-summary.json) is
preserved. Codex supplies named-skill compatibility evidence under that inherited
context; the adherence threshold is independently met by Claude and Pi.

## Limits and decision

Proceed to M1 under the accepted small-sample gate. These trials do not establish
production reliability, review quality, fresh-context contracts, compaction
behavior, or loops. Most fix stages recorded clean-review dispositions, so this
does not demonstrate a substantive repair loop.

Claude uses namespace-prefixed IDs while other fixtures use bare IDs. Canonical
skill-ID resolution and byte-identical rendering from one configuration remain
M1/M3 work. Keep the OpenCode environment blocker and Codex's bulk-loading
behavior visible when implementing the remaining adapters. The pipeline and skill
texts were unchanged throughout the experiment.
